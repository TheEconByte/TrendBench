# 구현 작업 목록

각 작업은 해당 완료 기준을 확인한 뒤 체크한다. 저장소 기반 구성과 제품 기능 완료는 구분한다.

## R0 — 저장소 기반

- [x] 이전 코드·인프라·문서를 legacy로 분리
- [x] README·AGENTS·제품 범위·실행 안내·작업 목록 정리
- [x] Next.js 시작 화면과 PostgreSQL 전용 개발 구성 작성
- [x] 의존성 설치·정적 검사·프로덕션 빌드·HTTP 응답 검증

PostgreSQL은 Compose 설정만 검증했다. 로컬 Docker 데몬을 실행한 뒤 컨테이너 기동 검증이 필요하다. 세부 결과는 REPOSITORY_REORGANIZATION.md를 따른다.

## F1 — 재무 계산 핵심 (다음 작업)

- [ ] Zod 입력 스키마: 원 단위 문자열, null, 음수·비율·기간 검사
- [ ] decimal 기반 필요자금·부족자금·운영수지·운영비 충당 매출
- [ ] 무차입·원금균등·원리금균등·거치 및 월별 잔액
- [ ] 기본·악화·개선 시나리오와 입력·계산 버전
- [ ] Vitest: 0금리·0대출·누락·변동비 100%·최종 잔액·반올림 검산

완료 기준: 기술 설계의 예제와 경계값을 독립 검산하고 DB·외부 API 없이 실행 가능. 사용자의 가정이며 예측이 아니라는 결과 표시.

## F2 — 인증과 계획 저장

- [ ] Prisma·Better Auth의 검증된 버전 및 인증 테이블 구성
- [ ] plans/plan_results migration, 입력·결과 스키마 검증
- [ ] 로그인·로그아웃·계획 입력·초안 저장·계산·재접속 조회
- [ ] 소유자 권한, 초안 revision 충돌, 결과 불변성·중복 계산 처리

완료 기준: 두 사용자 간 조회·수정·삭제·계산 차단. 미로그인 저장 차단. 기존 결과가 가정 수정 후 바뀌지 않음.

## F3 — 상권 데이터 연결

- [ ] 파일 기반 적재 명령, 출처·checksum·인코딩·헤더·코드·분기 검사
- [ ] 릴리스 단위 트랜잭션, 중복 적재 및 실패 시 기존 릴리스 유지
- [ ] 자치구→상권→업종 선택과 분기별 표·차트
- [ ] null·자료 부족·가용 분기·단위 미확정 표시

완료 기준: 검증된 실제 자료 사용, 재적재 중복 없음, 개인 예상매출 자동 대입 없음. 원본 입수 방법은 docs/verification/README.md 참고.

## F4 — 자금 후보

- [ ] 실제 운영용 공고 검수 및 JSON 버전 관리
- [ ] 유형·기준일·접수 상태·조건 PASS/FAIL/UNKNOWN 판정
- [ ] 후보 0건, 등록 이후 검토, 금리 미확정·지원하지 않는 상환 구조 처리

완료 기준: 종료·미검수 공고를 신청 가능으로 표시하지 않음. 지원금을 대출금으로 반영하지 않음. 가정 대출과 상품 확정 조건 구분.

## F5 — 비교와 출시 검증

- [ ] 결과 2개 비교·모바일·키보드 사용·이탈 경고
- [ ] Playwright 사용자 흐름·오류·복구 확인
- [ ] 이메일 전달·배포·백업 복구·개인정보 처리·로그 점검

완료 기준: 실제 사용자가 계획 입력부터 저장·비교까지 완료. 릴리스 데이터·상품의 확인일 명시. 미완료 항목을 출시 완료로 기록하지 않음.
