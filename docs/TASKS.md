## F3 — 상권 데이터 연결 (완료)

- [x] 파일 기반 적재 명령, 출처·checksum·인코딩·헤더·코드·분기 검사
- [x] 릴리스 단위 트랜잭션, 중복 적재 및 실패 시 기존 릴리스 유지
- [x] 자치구→상권→업종 선택과 분기별 표·차트
- [x] null·자료 부족·가용 분기·단위 미확정 표시

완료 기준: 검증된 실제 자료 사용, 재적재 중복 없음, 개인 예상매출 자동 대입 없음. 원본 입수 방법은 docs/verification/README.md 참고.

2026-09-18 완료 메모: `market_releases`, `market_areas`, `industries`, `market_quarterly` 모델과 migration `20260918121546_f3_market_data`를 추가했다. 적재는 `npm --prefix app run market:load`(app/scripts/load-market.ts)가 담당하며 ZIP 안 CP949 CSV와 Shapefile ZIP의 UTF-8 DBF 속성을 읽고, 2024년 한글·2025년 영문 점포 헤더를 각각 명시적으로 매핑한다. 활성 릴리스는 `seoul-market-2024q1-2025q4-c7dd7d3c3834`이고 상권 1,650건, 분기 지표 24,779건(매출 보유 19,909건 + 점포만 있는 4,870건은 매출 null)을 적재했다.

원본 대조 결과는 매출 172,911행, 점포 611,664행, 영역 1,650행, 점포 자료가 없는 매출 행 0건, 결합 키 중복 0건, 점포에만 있는 결합 키 438,753건, 점포 수 항등식 위반 0건이다. 같은 원본을 다시 적재하면 `ALREADY_ACTIVE`로 중복 행이 생기지 않고, 활성화 직전에 실패한 릴리스는 데이터를 정리하고 `FAILED`로 남기며 기존 활성 릴리스는 그대로 서비스된다. 자치구→상권→업종 선택과 분기별 표·차트는 `/markets`에서 로그인 없이 볼 수 있고, 공개 API는 `/api/industries`, `/api/markets/areas`, `/api/markets/summary`다.

남은 제약: 매출 원값의 월·분기 단위와 점포당 매출 모집단은 여전히 미확정이라 화면과 API가 단위 미확정과 자료 부족을 표시만 한다. 2026년 자료는 검증하지 않았고, 상권 코드 3110024는 영역 파일과 매출·점포 파일의 명칭이 달라 두 명칭을 함께 보존한다.

2026-09-20 보완: 업종 메타데이터를 릴리스별로 격리해 실패한 적재가 활성 릴리스 응답을 바꾸지 않도록 했다. 운영 적재의 checksum 우회 옵션을 제거했고, DB 변경 테스트는 `TEST_DATABASE_URL` 전용 DB에서만 실행한다. 상권 목록의 오래된 비동기 응답 차단과 좁은 화면 결과 영역의 가로 넘침도 수정했다.
